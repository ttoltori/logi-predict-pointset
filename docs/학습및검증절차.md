## 0. 사전 지식: 이 프로젝트가 하는 일

- **입력**: 물류 상품의 단일 이미지 (227×227 RGB, bbox crop)
- **출력**: 11,000개의 3D 좌표점 (x, y, z) — 포인트 클라우드
- **방법**: SqueezeNet 1.1 백본으로 이미지 feature 추출 → 1×1 Conv + FC로 각 점의 3D 좌표 회귀
- **손실**: Chamfer Distance (예측 점과 정답 점 사이의 양방향 최근접 거리)
- **활용**: 물류 박스의 3D 형태 복원 → 부피 추정 → 물류 비용 계산

### 전체 워크플로우

```
NIA29 원본 데이터 (JPG + JSON)
        │
        ▼ prepare_data_3d.py (전처리)
        │
  ┌─────┴─────┐
  │  datasets/ │
  │  images    │ → PNG (폴리곤 crop)
  │  labels    │ → NPY (박스 포인트 클라우드)
  │  json      │ → JSON (치수 정보)
  │  train/val/test txt
  └─────┬─────┘
        │
        ▼ baseline_main.py (학습)
        │
  ┌─────┴─────┐
  │ 체크포인트  │
  │ best-*.pt │
  └─────┬─────┘
        │
   ┌────┼────┐
   ▼    ▼    ▼
 eval  test  Volume
 (IoU) (시각화) (부피)
```

## 2. 데이터 전처리 (prepare_data_3d.py)

### 2.1 왜 전처리가 필요한가

A-Point-Set-Generation 모델은 "단일 이미지 → 3D 포인트 클라우드"를 학습한다.
하지만 NIA29 원본 데이터에는 3D 스캔 포인트 클라우드가 없다.
대신 JSON 라벨에 상품의 물리적 치수(`length`, `width`, `height`)가 있으므로,
**박스 형태의 포인트 클라우드를 합성**하여 정답(GT)으로 사용한다.

이는 "물류공간 예측" 목적에 부합한다 — 상품이 차지하는 공간을 박스로 근사.

### 2.2 원본 데이터 구조 (입력)

```
Sample/                                    ← --src 로 지정
  01.원천데이터/
    02_출고물품/                            ← --category outbound
      <대분류>/<중분류>/<KAN>_<id>/
        <KAN>_<id>_<shot>_<cam>.jpg         ← 원본 이미지 (1920×1080)
  02.라벨링데이터/
    02_출고물품/
      <대분류>/<중분류>/<KAN>_<id>/
        <KAN>_<id>_<shot>_<cam>.json        ← COCO-like 라벨 (치수, 폴리곤, bbox)
```

**JSON 라벨에 포함된 필드**:
```json
{
  "annotations": [{
    "bbox": [787, 340, 325, 222],           ← 바운딩 박스 [x, y, w, h]
    "segmentation": [[791, 340, 787, 550, ...]],  ← 폴리곤 좌표
    "attributes": {
      "length": 30.0,                       ← 박스 길이 (cm)
      "width": 20.0,                        ← 박스 너비 (cm)
      "height": 12.0,                       ← 박스 높이 (cm)
      "KAN_code": "01010102",
      "barcode": "8809162740524"
    }
  }]
}
```

### 2.3 전처리 출력 구조

```
datasets/                                   ← --dst 로 지정
  images_poly_bbox_crop/                    ← data_loader.py의 image_root
    <KAN>_<id>_<shot>_<cam>.png             ← 폴리곤 crop PNG
  labels/                                   ← data_loader.py의 point_cloud_root
    npy_stride5/
      <KAN>_<id>_<shot>_<cam>.npy           ← 박스 포인트 클라우드 (11000×3)
  json_labels/                              ← Volume_estimation.py의 json_root
    <KAN>_<id>_<shot>_<cam>.json            ← 치수 정보 JSON
  train_data.txt                            ← 학습 파일명 리스트 (80%)
  val_data.txt                              ← 검증 파일명 리스트 (10%)
  test_data.txt                             ← 테스트 파일명 리스트 (10%)
```

### 2.4 전처리 스크립트가 수행하는 작업

`prepare_data_3d.py`는 4가지 작업을 수행한다:

1. **이미지 폴리곤 crop**:
   - JSON의 `segmentation`(폴리곤)으로 마스크 생성
   - 폴리곤 외부를 흰색으로 채우고 `bbox`로 잘라냄
   - PNG로 저장 (무손실 압축)
   - 왜: 배경을 제거하여 모델이 상품 영역에 집중하도록 함

2. **박스 포인트 클라우드 생성**:
   - JSON의 `length`/`width`/`height`(cm)로 박스 표면에 점 생성
   - 6개 면에 5mm 간격(`stride=0.5cm`)으로 그리드 점 배치
   - 11000개로 리샘플링 (부족하면 복원 추출, 많으면 비복원 추출)
   - NPY로 저장 (`(11000, 3)` float32 배열)
   - 좌표계: 원점=박스 중심, x=width, y=length, z=height

3. **간소화 JSON 저장**:
   - `Volume_estimation.py`가 필요한 치수 필드만 추출
   - 원본 JSON에서 segmentation, area 등 불필요한 필드 제거

4. **데이터 분할**:
   - 상품(leaf 폴더) 단위로 train/val/test 분할 (8:1:1)
   - KAN_code 기준 stratified 분할 (클래스별 고르게 분포)
   - 랜덤 시드 169 (`split_data.py`와 동일)
   - 왜 상품 단위인가: 동일 상품의 여러 이미지가 여러 셋에 섞이면 데이터 누수 발생

### 2.5 전처리 실행

```bash
# 기본 실행 (출고물품, ../Sample → datasets)
python prepare_data_3d.py

# 경로 지정
python prepare_data_3d.py --src ../Sample --dst datasets

# 입고물품 전처리
python prepare_data_3d.py --category inbound

# 기존 출력 삭제 후 재생성
python prepare_data_3d.py --clean

# 분할 결과만 확인 (파일 생성 없음)
python prepare_data_3d.py --dry_run

# 포인트 수 변경 (모델 num_points와 일치해야 함)
python prepare_data_3d.py --num_points 5000

# 분할 비율 변경
python prepare_data_3d.py --train_ratio 0.7 --val_ratio 0.15 --test_ratio 0.15
```

**주요 인자**:

| 인자 | 기본값 | 설명 |
|------|--------|------|
| `--src` | `../Sample` | 원본 데이터 루트 |
| `--dst` | `datasets` | 출력 데이터 루트 |
| `--category` | `outbound` | `inbound`(입고) \| `outbound`(출고) |
| `--stride` | `0.5` | 포인트 클라우드 그리드 간격 (cm) |
| `--num_points` | `11000` | 포인트 수 (모델 `num_points`와 일치) |
| `--train_ratio` | `0.8` | 학습셋 비율 |
| `--val_ratio` | `0.1` | 검증셋 비율 |
| `--test_ratio` | `0.1` | 테스트셋 비율 |
| `--seed` | `169` | 분할 랜덤 시드 |
| `--clean` | (플래그) | 기존 출력 삭제 후 재생성 |
| `--dry_run` | (플래그) | 파일 생성 없이 통계만 출력 |

**학습 로그**: 콘솔에 실시간 출력

```
Epoch: [1/50] | Batch: [1/26] | Loss: 0.3804 | mIoU: 0.1799 | Time: 0:00:15
```

**체크포인트 위치**:

**로그에서 확인할 지표**:
- `Loss`: Chamfer Distance 손실 (낮을수록 좋음)

## 6. 문제 해결 가이드

### 6.1 전처리 관련 오류

| 오류 | 원인 | 해결 |
|------|------|------|
| `[오류] 원천데이터 디렉토리가 없습니다` | `--src` 경로 오류 | `Sample/` 폴더가 있는 경로 지정 |
| `[오류] 카테고리 폴더가 없습니다` | `--category` 오류 | `inbound` 또는 `outbound` 확인 |
| `[경고] JSON 누락` | 이미지에 대응하는 JSON 없음 | 원본 데이터 누락, 스킵됨 |
| `[경고] bbox가 무효함` | JSON의 bbox 값 오류 | 해당 이미지 스킵됨 |
| `[경고] 치수가 무효함` | length/width/height가 0 또는 음수 | JSON 라벨 오류, 해당 이미지 스킵됨 |
| `[오류] ... : ...` | JSON 파싱 실패 | JSON 파일 손상, 해당 이미지 스킵됨 |

### 6.2 학습 관련 오류

| 오류 | 원인 | 해결 |
|------|------|------|
| `FileNotFoundError: Image file not found` | 데이터 경로 불일치 | `--image_root` 인자로 올바른 경로 지정 |
| `ModuleNotFoundError: chamfer_distance` | pytorch3d 미설치 | Linux: pytorch3d 빌드, Windows: `chamfer_distance.py` 자동 사용 |
| `RuntimeError: CUDA out of memory` | batch_size 너무 큼 | `--batch_size` 감소 (RTX 5060 8GB: 4~8) |
| `RuntimeError: DataLoader worker` (Windows) | 다중 워커 문제 | `--num_workers 0` |
| SqueezeNet 다운로드 실패 | 인터넷 연결 문제 | 수동으로 사전학습 가중치 다운로드 |
| `no kernel image` (RTX 50xx) | CUDA 12.8 미만 PyTorch | CUDA 12.8 이상 PyTorch 설치 |
| 포인트 클라우드 shape 불일치 | `num_points` 불일치 | `prepare_data_3d.py --num_points`와 `--num_points` 일치 확인 |

### 6.3 학습이 안 될 때 점검 순서

1. **전처리 완료 확인**: `datasets/` 디렉토리에 PNG, NPY, JSON, txt 파일이 있는지
2. **데이터 경로**: `--image_root`, `--point_cloud_root` 인자가 올바른 경로를 가리키는지
3. **데이터 분할**: `train_data.txt` 등에 파일명이 정상적으로 저장되었는지
4. **이미지-포인트클라우드 쌍**: XDataset 초기화 시 "Found N image-pointcloud pairs" 로그 확인
5. **GPU 확인**: `nvidia-smi`로 GPU 상태 확인
6. **Chamfer Distance 확인**: `python -c "from chamfer_distance import ChamferDistance; print('OK')"` (Linux: pytorch3d, Windows: chamfer_distance.py)
7. **메모리 확인**: `--batch_size 1`로 줄여서 테스트
8. **num_points 일치**: 전처리 `--num_points`와 모델 `--num_points`가 같은지

### 6.4 mIoU가 오르지 않을 때

- **데이터 품질**: 포인트 클라우드가 박스 형태이므로, 모델이 박스 형태를 학습하는 것이 정상
- **학습률**: 0.001이 너무 크거나 작을 수 있음. `--learning_rate 0.0001~0.01` 범위에서 실험
- **epoch 수**: 50으로 부족할 수 있음. `--num_epochs 100~200`으로 증가
- **num_points**: 11000이 너무 많아 학습이 어려울 수 있음. 2500~5000으로 축소 시도
  (축소 시 `prepare_data_3d.py --num_points N`으로 재전처리 + `--num_points N` 일치 필요)
- **데이터 증강**: 현재 augmentation 없음. RandomFlip, RandomRotation 등 추가 고려
- **데이터 양**: 샘플 데이터(251장)는 학습용으로 부족. 전체 데이터로 전처리 권장

### 7.1 전처리 실행

```
NIA29 출고물품 데이터를 A-Point-Set-Generation 학습용으로 전처리해줘.
```

```
NIA29 출고물품 데이터로 A-Point-Set-Generation 모델을 학습하고 싶어.
다음을 순서대로 수행해줘:
1. prepare_data_3d.py로 전처리 (../Sample → datasets, outbound)

```

### 7.3 Windows 디버깅 학습

```
Windows 환경에서 A-Point-Set-Generation 모델을 학습하고 싶어.
다음 인자로 실행해줘:
- --num_workers 0
- --batch_size 4
- --num_epochs 3
- chamfer_distance가 import 되는지 확인 (Windows: chamfer_distance.py 자동 사용)
오류가 발생하면 원인을 분석하고 수정해줘.
```

### 7.4 평가 실행

```
학습된 best-Baseline_DL_Vis.pt 체크포인트로 eval.py를 실행해서
테스트 데이터셋의 평균 IoU를 계산해줘.
결과 로그를 확인하고, IoU가 낮은 항목들을 찾아줘.
```

### 7.5 시각화

```
학습된 모델로 테스트 데이터 일부를 시각화해줘.
```

### 7.6 학습 재개

```
학습이 중단되었어. 중단된 시점부터 이어서 학습하고 싶어.
baseline_main.py에 --use_checkpoint 플래그를 추가하고 실행해줘.
학습 로그(Baseline_DL_Vis JSON)에서 마지막으로 완료된 epoch를 확인하고

```
